# 项目

项目主数据：代码、客户、进度与合同金额。

项目代码几乎出现在每一份单据中——采购订单、采购、报销、销售发票。本菜单赋予这些代码以
含义：工程叫什么、客户是谁、合同金额多少。

## 项目代码不可更改

这是最重要的一点。

代码是项目与所有提及它的单据之间的**唯一纽带**。更改代码会切断每一笔引用旧代码的采购、
采购订单与发票——且不会出现任何报错，只留下突然失去归属的单据。

因此，项目一经创建，代码即被锁定。保存前请核对拼写。代码已经填错的项目必须删除后重建
——前提是尚无单据使用它。

## 创建项目

| 字段 | 说明 |
|---|---|
| 项目代码 | 4–5 个字符，大写，不可更改 |
| 项目名称 | 工程的完整名称 |
| 客户 | 委托方 |
| 开始与结束日期 | 合同工期 |

创建项目的权限限于级别 4 及以上，正是因为代码日后无法更正。

## 项目的三种状态

| 状态 | 含义 |
|---|---|
| **进行中** | 工程仍在进行 |
| **已完成** | 工程已竣工 |
| **已取消** | 工程在完成前被取消 |

已取消的项目**不予删除**。已就其发生的成本仍记录在采购与报销中；若删除该项目，这些成本
便成为孤项——计入公司总额，却无所归属。

标记为已完成或已取消也能整理代码选择器：两者仍作为选项出现，但排序至最末并加以标注。

## 合同与补充协议

合同金额**并非手工填写的单一数字**，而是项目明细页面上各份单据的合计。

先为原始工作指令书添加一行，再为每份补充协议各添加一行。变更历史由此保持完整——而在
审计年度，“合同金额为何与原始工作指令书不同”是一个必须能以单据回答的问题。

### 填写一份合同单据

| 字段 | 说明 |
|---|---|
| 单据编号 | 工作指令书或补充协议编号 |
| 类型 | 工作指令书或补充协议 |
| DPP | 计税基础，不含增值税 |
| 增值税 | 百分比 |
| 预扣税 | 选填，从税务对象列表中选择 |
| 日期 | 单据日期 |

请填写 **DPP**，而非含增值税的金额。表单下方的摘要会显示增值税金额、单据金额，以及
扣除预扣税后的实收金额——保存前请核对这三项。

**缩减工作范围的补充协议应填为负数。**合同金额随之减少，而缩减的过程仍清晰可查。

## 报表中的合同金额采用 DPP

项目报表以 **DPP** 计算毛利，而非含税总额。增值税是代国家保管的款项，并非收入——采用
含增值税的金额，会使每个项目的毛利看起来比实际高出约百分之十一。

这足以使一个实际上小幅亏损的项目显得盈利。

## 项目报表的两种视图

**概览**回答*钱花到哪里去了*：按类别划分的成本构成，且每个类别均可展开查看按供应商
划分的明细。

顶部的横条以百分比显示合同金额在成本与毛利之间的划分。低于百分之八的数字会特意不在
横条中显示——在过窄的区段中，文字会被截断而无法辨读。其卢比金额仍保留在下方图例中。

若成本超出合同金额，横条将变为红色并显示超出的幅度。

**每周流水**回答概览无法回答的问题：资金*何时*流出，以及开票是否跟得上。

采用每周而非每月，是因为此处的项目通常工期较短——按月只会产生三四根柱形，无法反映
节奏。

此处需要留意：

- **每周自周一起算。**现场工作与开票均以工作周为准；若以周日切分，会将一个工作周拆成
  两根柱形。
- **无交易的周份仍会显示。**若将其略去，三周的停顿看起来会与连续两周一样紧凑——而恰恰
  是这段停顿标志着工程已经停工。
- **累计成本**会与合同金额相比对。若曲线已逼近上限而工程才完成一半，此时即可发现，而
  非等到超出之后。
