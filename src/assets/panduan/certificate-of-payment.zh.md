# 付款证书 (CoP)

针对 SPK 的进度报告 —— 对分阶段完成的工作进行计费的依据。

付款证书记录一张 SPK（工作指令单）上**已完成的工作量**，然后计算可据此
计费的金额。一张 SPK 可以有多张 CoP —— 每个进度周期一张（按周、按期等）。

> 重要：CoP 仅用于 **SPK**，不用于货物采购订单。货物一次收货、一次计费，
> 通过**采购**菜单办理；对其按周计进度没有意义。**A** 和 **D** 类型也被
> 排除 —— 它们的计费由另一条路径处理。

<a id="alur-empat-tahap"></a>

## 四个阶段的流程

这是最重要的部分。CoP 要经过**四个阶段**、**两次审批**，每个阶段由不同的人
经手 —— 这是有意为之：记录进度的人不是确认进度是否真实的人，也不是填写价格
的人，更不是签发账单的人。

| 阶段 | 谁 | 做什么 |
|---|---|---|
| **1. 创建 BAP** | 现场（工程 **1 级**） | 填写工作**量**。价格永远不会到这里。 |
| **2. 审批 BAP** | **4 级及以上** | 确认现场进度。只有**在此之后**才可填写价格。 |
| **3. 创建 CoP** | 复核人（工程 **2 级**及以上） | 填写**价格与扣款**（预付款、保留金、罚款、加项）。 |
| **4. 审批 CoP** | **4 级及以上** | 审批最终金额。此后即**可计费**。 |

两次审批（BAP 与 CoP）**不能由同一人完成**，也不能由创建者本人完成。这正是
对每份文件保持"第二双眼睛"的保障。

BAP 与 CoP 是一个文件里的**两份文件**：**BAP** 说明**做了什么**（工作量，
带到现场核查），**CoP** 说明**付多少钱**。因此各自都有自己的"创建人"和
"审批人"。

<a id="mengisi-volume"></a>

## 阶段 1 —— 填写工作量（现场）

现场人员打开已审批的 SPK，填写本期每一行工作的**工作量**。界面只显示工作量
和剩余预算 —— **单价永不发送到现场界面**，因此现场任何人都读不到。

每一行都有**预算（pagu）**：该行的合同工作量减去其他 CoP 已认证的部分。
超过剩余预算的工作量将被**拒绝** —— 如果工作确实增加，必须先对 SPK 进行
**补充协议**（补充协议是一份单独文件，记录差额，有自己的行）。

工作周期（起止日期）为**必填**。若与同一 SPK 上的其他 CoP 周期重叠，系统会
**提示** —— 但不阻止，因为修正后重新认证有时确实会复用同一区间。

<a id="setujui-bap"></a>

## 阶段 2 —— 审批 BAP

工作量无误后，**4 级及以上**按下**审批 BAP**。这确认现场进度确实发生。
在此步骤之前：

- 价格与扣款**完全不能**填写。
- 工作量**仍可**编辑。

BAP 审批后，工作量被锁定（如需更改，先取消 BAP 审批）。

<a id="buat-cop"></a>

## 阶段 3 —— 创建 CoP（填写价格与扣款）

这里**首次出现金额**。复核人（工程 2 级及以上）打开 CoP 表单，填写**扣款**
与**加项**：

| 扣款 | 用于 |
|---|---|
| **预付款** | 摊销预先支付的预付款。 |
| **保留金** | 保留至维护期结束。 |
| **罚款** | 逾期或质量。 |
| **其他** | 意外情况（须填写说明）。 |

加项用于**合同之外**的费用（代垫运费、意外动员）。加项**不得**承载工作量 ——
增加的工作仍须通过补充协议。

> **预扣所得税 (PPh)** 有意**不**列入 CoP 扣款清单。它在**采购**上扣除一次，
> 而非在此处。在 CoP 表单上，预扣税仍**显示**为适用税率的说明，但不计入
> 扣款合计 —— 以免被扣两次。

预付款与保留金扣款有**预算**：其返还总额不得超过实际支付/约定的金额。系统
按比例计算建议金额。

<a id="setujui-cop"></a>

## 阶段 4 —— 审批 CoP

**4 级及以上**（不是刚才审批 BAP 的人）按下**审批 CoP**。自此 CoP **可计费**，
其扣款/加项被锁定 —— 已审批的金额就是将要计费的金额。

<a id="penomoran"></a>

## 编号

CoP 编号按以下格式自动生成：

```
[序号]-[供应商 ID]-[项目代码]-[年份]
```

例如 **`002-042-R501-2026`** —— 供应商 42 在项目 R501 于 2026 年的第二张
CoP。序号**按供应商 + 项目**递增，供应商 ID 补足三位。该编号会同时打印为
**No. CoP** 和 **No. BAP**。

<a id="mencetak"></a>

## 打印

- **BAP** 可**随时**下载，甚至在处理之前 —— 它说明的是工作量而非金额，而这
  正是带到现场核查的那张表。
- **CoP** 只能在**创建之后**（价格与扣款已填）下载 —— 在此之前数字未经任何
  人审阅，而提前从打印机出来的表与正确的表无法区分。

1 级（现场）不能下载 CoP 表：它含有单价和合同金额。

<a id="dari-ponsel"></a>

## 从手机审批

两次审批 —— **审批 BAP** 与 **审批 CoP** —— 都可通过手机应用的 **CoP 审批**
菜单完成。等待决定的项目会显示其阶段标记（"等待 BAP 审批" / "等待 CoP
审批"）。填写价格仍在办公室电脑上进行 —— 多列的预算表无法在移动中正确填写。

<a id="menagihkan"></a>

## 对 CoP 计费

**已审批且尚未计费**的 CoP 会出现在**采购**表单中作为计费依据。一张 CoP 只能
作为一笔有效采购的依据 —— 删除其采购会自动重新开放该 CoP。
